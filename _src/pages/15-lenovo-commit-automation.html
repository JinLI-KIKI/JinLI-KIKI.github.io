The problem

Commits arrive part by part: so many boards, panels, keyboards and batteries, by week and by factory. A notebook, the "box", ships only when every part it needs is there. Turning hundreds of part commits into box commits meant matching part numbers to products, checking which factory had which material, and finding the part that held each product back.

Done by hand, this took a large share of every planning week. It also missed a quieter problem: material sitting at one factory that an order needed at another, or built with the wrong origin for where the order was going. Those mismatches showed up later as delivery delays.

How it works

  1. Input

    Part commits

    Supplier and factory commits by part number, site and week.

  2. Step 1

    Explode the BOM

    Map each box to the parts it needs.

  3. Step 2

    Find the constraint

    For each box, site and week, the scarcest part sets how many can be built.

  4. Step 3

    Match across factories

    Point material at the site and order that can use it, respecting origin.

  5. Output

    Box commits

    Finished-unit commits the team could use and share directly.

What it taught me

Automate the weekly pain

The tool paid off because it replaced work the whole team repeated every week, not because the logic was complicated.

The constraint is the answer

Planners don't need every number. They need to know which part is holding each product back, so that is what the output led with.

Origin is data

Once tariffs depended on where a board was made, origin had to be a field in the matching logic, not something people remembered.

Build for the people using it

Output had to look like what planners already shared, or it wouldn't be used.
